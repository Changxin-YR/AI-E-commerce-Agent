# SoloOps R2 基础版缺陷修复与用户体验收敛范围

日期：2026-10-10。目标是修复已确认缺陷、降低个人跨境卖家的操作门槛，保持四条现有闭环。执行状态见 [进度](r2-fix-progress.md)。

## 顺序与包级门槛

严格依次执行四包，每包定向测试、独立提交 Git、推送并确认准确提交 SHA 的 GitHub Actions CI 成功后进入下一包。无需逐包再次取得常规开发许可；真实外部操作、生产数据、高风险设计或范围外事项另行确认。遇到上下文上限按 AGENTS 的既有授权落盘、推送并创建接续聊天，交接后旧聊天停止写入。

开工须读 AGENTS、V1.0/R2、r2-progress、r2-c-acceptance、r2-deployment-gates、feature-matrix、两份报告及相关源码；核对 HEAD/工作区/迁移/CI。第二份原题为“真实卖家使用验收报告”，实际为 Codex 使用合成数据与浏览器执行的模拟卖家使用验收，没有独立真人参与。870/128/78 是历史基线，不能冒充修复后结果。

## 包 1：P2-01 来源一致性

B1 读取当前 Listing 后，另行批准新 Listing，首次 GET /api/workbench 就须给出 stale / 需要重新核对，不能先打开详情才更新。首页与详情共用来源判断；工作台 GET 不写业务数据、不推进 Agent，不逐任务调用完整 Agent 服务。列表/计数/分页一致，保留原审批/来源版本/历史/幂等，独立商品变化不误阻断其他任务，不将全部 B1 一律标为 stale。

保留并通过 `test_b1_inbox_reflects_changed_listing_before_opening_task`；覆盖首页首次读、详情、计数、跨店、旧审批、无关商品、重复刷新、恢复与清除。包级证据见 [P2-01](r2-fix-p2-01.md)。

## 包 2：UAT-03 / UAT-04 输入与连续性

日期与时区：优先原生 Vue/HTML 控件或轻量组件，选择日期和时间；显示业务 IANA 时区与最终范围，适用处提供最近 7 天/30 天快捷选择。保持 UTC 持久化和分析窗口 `[起点, 终点)`。夏令时歧义/不存在时间不能静默修正；高级用户仍能输入原有精确时间表达式。

Agent：优先合法 URL 参数与当前任务记录恢复店铺、数据身份、渠道和任务对象。历史任务只读回显不代表新任务获授权；再次运行须重新核对范围、预算及审批。刷新不能自动启动新 Agent。

客服：保存草稿后保留深链，刷新能定位当前草稿与保存历史。跨店、失效、撤销、清除、无权对象给准确提示；未保存编辑不得被静默覆盖；恢复状态不能触发发送。

1440px 桌面与 390px 手机验收日期选择、切店、刷新、后退/前进、Agent 暂停恢复、客服编辑保存和历史回读。保留权限、来源和审批安全测试。

## 包 3：UAT-02 大文件入口

先提交最小技术方案，评估受限前端文件选择、拆分、分片上传与恢复，复用现有 import_split.py 和导入组协议。说明 CSV 引号/转义/换行/UTF-8 BOM/多行字段、原始字节/行数/SHA256/manifest 一致性，以及浏览器内存/取消/中断/恢复的边界。维持去重、覆盖、回退保护；不能推翻 manifest、批次恢复及撤销机制。

少量可维护代码能够安全实现则实施；若需要复杂解析框架或大规模导入系统修改，停止自动拆分部分，记录方案/风险并请求用户确认。无论是否实现自动拆分，必须改善超限提示、可执行下一步、分片进度/失败原因、导入记录对账与分析容量差异提示。

不能取消 2 MiB/2000 行单片限制、静默截断、隐式改业务键或放宽危险文件检查。现有分组最多 40000 行；仍有 10000/1000 行限制的分析/核对功能须明确告知，超限拒绝不能显示不完整的成功汇总。

合成验收至少含 2001/10001 行、跨片重复订单、部分上传失败继续、取消和整组撤销、退款/币种/日期/异常单元格、重复导入不重复累计、完整性和来源回读。

## 包 4：UAT-01 首次使用

默认交付模式是管理员预先部署，卖家取得账号后通过网页经营。检查现有交付方式，完善首次使用说明、账号获取、建店与首次导入引导。正式管理员 CLI 建号保留；自助注册或公开用户管理需要单独安全设计与用户确认。卖家得到账号后四条核心流程应无需命令行、数据库操作或直接调用 API。

## 最终业务回归与交付

- MVP-01：导入 → 异常 → 待办审批 → 人工处理 → 新来源复检 → 回读；人工完成不等于问题解决。
- MVP-02：商品事实 → AI/本地候选 → 编辑 → 审批 → 本地生效 → 复制/CSV → 来源变更重核；不称平台已发布。
- MVP-03：导入消息 → 订单/政策 → 多意图 → 敏感接管 → 审阅 → 导出 → 人工证据；不称已向真实买家发送。
- MVP-04：订单 → 销售统计 → 当前/历史成本区别 → 数值与来源 → 保存分析 → 待办 → 来源变更重算；Decimal/Numeric，不推断精确净利润。
- 复核 B1 低毛利跨技能分支、逐节点审批、执行预算、断点恢复与受控内部写入。

最终提交前完成当前项目 Ruff/mypy/pytest、ESLint/TypeScript/build、Vitest、Playwright、准确 GitHub CI。每包记录修改文件/原因、修复前后证据、实际业务记录与状态、是否迁移/影响旧数据、回退、Commit SHA 与 CI 链接。不得降低正确断言或忽略失败。真实权限/数据安全缺陷优先定点处理，不扩大长期范围。

最终报告名为《SoloOps R2 基础版缺陷修复与用户体验收敛报告》，包含 P2-01 原失败测试复验、UAT-01～04 最终状态、彻底修复/仅体验改善/明确延期、四 MVP 退化判断、B1 内部写入、自动化与 CI、最终 SHA、数据迁移/回退边界、仍待真人/真实报表/公网验证事项。最终完成后停止开发。
