# SoloOps 三端业务实现方案 V1.3 · 鸿蒙优先

更新：2026-10-11。执行依据：用户最新指令。本文件是当前移动开发主计划。

## 目标与执行方式

完整实现 R2 基础业务版的移动功能。当前只开发鸿蒙，目标运行设备为 API 22 模拟器。先完成全部业务页面、接口调用和系统能力，再集中进行模拟器自查，随后与用户逐项联调。开发期间只处理阻碍实现的编译与接口问题，不以逐包验收、CI、真机或其他客户端进度作为继续开发的前置条件。

范围依据原《三端开发方案 V1.2》、现有 R2 代码、`contracts/ui-contract.json`：19 个业务路由、登录、B1 专项，共21个功能标识和149条 API 引用。原 V1.0 的74项SO仍是产品长期总账；本次“全部功能”按主体文档的 R2 完整业务范围落地。旧方案归档为 `SoloOps-Mobile-V1.2-reference.md`，其 M0/M1 分阶段等待审批、仅诊断壳、真机准入等执行顺序由本文件替代。

“解除限制”落实为连续开发授权，包括后端移动认证、必要迁移、正式业务页面与系统桥接。原产品的店铺归属、审批、版本冲突、凭据保护和业务事实语义属于功能实现本身。模拟器与隔离合成数据足以完成本轮开发验收；真实店铺、付费模型或真实邮件不作为开发依赖。

## 三端分别怎样实现

| 层次 | 鸿蒙：当前实施 | Android：后续独立一轮 | 微信：后续独立一轮 |
|---|---|---|---|
| 页面 | 固定 Flutter OH 3.27.5-ohos-1.0.7 / Dart3.6.2，五入口和全部R2子页 | 复用同一Dart页面与状态管理 | Taro4 + Vue3 + TypeScript，按业务契约独立实现 |
| 状态与接口 | Dart service / repository / ChangeNotifier，HTTPS与不透明Bearer；切店使旧响应失效 | 复用Dart接口和模型 | Taro.request，对齐同一OpenAPI与状态语义 |
| 登录存储 | ArkTS Asset服务保存设备会话，preferences保存地址/店铺等非敏感设置 | Android Keystore | 内存短期会话，重开登录 |
| 文件 | ArkTS DocumentViewPicker、CoreFileKit，原字节上传既有ImportService；下载保存/ShareKit | Android系统文件选择与分享 | chooseMessageFile/uploadFile + 后端multipart薄适配 |
| 后端 | FastAPI → 原R2 Service/Agent → Repository → MySQL，增加移动会话适配 | 使用同一后端 | 使用同一后端 |
| 运行验收 | API22模拟器完整卖家旅程；最后集中检查 | 鸿蒙完成后再做Android模拟器 | 两个原生端阶段后进入开发者工具 |

API22是运行兼容目标。已锁定Flutter版本；本机编译SDK现为24，不把编译SDK标签当作设备运行版本。使用API22已有能力，最终以API22安装、启动和功能运行判断。当前不因换编译SDK额外返工。

## 连续开发顺序

1. 会话和网络、系统存储/文件桥接、主题和五入口、业务路由、店铺上下文。
2. 初始化和导入，使后续功能获得真实本地数据库输入。
3. 首页/待办/AI/B1、Listing、客服四条核心闭环。
4. 库存、分析/总览、利润、费用、账单/核对/回款、规则、定时、商品质量/修订和外发管理，补全所有R2入口与操作。
5. 全部实现后，一次性进行静态/编译与API22模拟器集中自查；修复影响运行的缺陷，输出可安装运行版本。
6. 与用户共同联调、优化交互和细节；鸿蒙完成后才切换下一端。

用户不需要在上述步骤之间重复批准。编码中可执行必要的构建/类型反馈来排除无法继续实现的问题；完整业务测试和UI微调放在功能覆盖完成之后。提交和进度保存用于恢复上下文，不构成阶段停工点。

## 记忆和接续

`docs/mobile/harmony-implementation-progress.md` 是实时账本：已完成文件、未完成动作、运行环境、下一步精确起点。上下文接近满时提前更新，保存/提交/推送当前成果，创建新对话持续开发，并给出精确SHA与该账本路径。新对话复用当前工作区，旧对话停止写入。计划和需求不随换对话重置。

模拟器一次仅一台，桌面与后台均适用；编码不需要设备时关闭，安装和运行阶段再启动鸿蒙22，保留数据。其他端本轮只保留计划。
