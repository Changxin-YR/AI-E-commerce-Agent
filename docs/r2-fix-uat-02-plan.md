# R2 修复包3：浏览器大报表入口最小方案

2026-10-10。前置包2业务提交5216da4的CI38053971553成功。范围为SO-001与既有导入组体验。本方案先提交，再实现与验证。

## 实现决定

沿用`import_split.py`的CSV与`soloops-split-v1`契约，在浏览器Worker中用小型确定性解析器生成相同分片。原文件最多40MiB、40000个数据记录、20片；每片最多2MiB/2000记录、64列、每格2000个Unicode字符。无需新依赖、数据库结构或服务器大文件接口。服务器继续独立验证危险内容、行数、字节、SHA256、映射、来源和权限。

选原UTF-8 CSV → 本机拆分 → 显示总记录/片数 → 按当前来源建组 → 逐片点击上传 → 原映射/纠错/语义与覆盖确认 → 提交 → 对账。各片仍由卖家确认，提交不自动批准下一片。CLI清单/分片兼容入口保留。

## 字节和记录契约

- UTF-8严格解码，接受开头BOM；无效编码、NUL、无表头、重复/空表头、超列/超格、未闭合或非法闭合引号拒绝。支持逗号、双引号转义及引号内CR/LF，CRLF/LF/CR按完整CSV逻辑记录划分。空行保留为记录，不用换行符计数代替记录数。
- 与Python默认`csv.writer`一致：UTF-8 BOM、必要引号、双引号翻倍、CRLF记录分隔。业务值不裁剪或补造。原件SHA256独立保存，规范化分片逐片写入字节/行数/指纹，行数总计相等；重编码片哈希不能冒充原件哈希。
- 多行字段的批次来源行号仍为片内物理行号；组页另显示连续原文件数据记录范围（不含表头），保留原文件名/指纹/片名并解释坐标。与现有Python工具逐字节及manifest对照，防两端实现偏离。

## 内存、取消和恢复

Web Crypto digest不支持流式输入；原件哈希阶段最多一次读取40MiB字节。解析使用64KiB块和有界当前记录，不保留完整字符串或行矩阵；分片最多20×2MiB，哈希最多额外读取一片。Worker保障主页面响应，内存不足安全失败。Web Crypto缺失提示使用HTTPS/可信本机或管理员辅助。

取消拆分立即terminate Worker并丢弃未完成结果，拆分不请求业务API。离页/切店终止计算并释放本机文件，不在localStorage/IndexedDB存正文。刷新后选择服务器原组与同一原文件，重新生成并完整比较manifest，匹配才允许上传。进度以持久组/批次为准：成功片显示完成，待审片可打开；网络故障重试原片沿原幂等机制回读，不推断失败请求是否已落盘。

结束本机处理仅释放文件，已建组须继续或显式整组撤销；整组撤销复用原事务/版本保护及回退，保留组外版本。覆盖仍要确认，跨片同键异值仍拒绝。

## 提示、验证与回退

建组前说明40000导入、10000分析/运营及部分核对1000限制；超限给出按明确时间/业务范围重新导出的步骤，单日超限明确当前不能提供完整该日汇总。失败片区分未上传/待纠错/可重试；可展开来源指纹与行数对账；单文件超限提供本页入口链接。

CSV单元与Python对照覆盖2001/10001记录、BOM/引号/多行/Unicode、2MiB划片、总量上限、坏文件及取消。1440/390真实浏览器覆盖跨片重复、部分网络失败继续、刷新重新匹配、重导不累计、退款/币种/日期/危险格、部分覆盖阻断及整组撤销。原后端导入/导入组套件复验权限、覆盖、事务回退和来源。每包提交后等待准确SHA CI。

改动集中于CSV模块、Worker、文件准备组件及ImportGroups/ImportsView，小函数和明确类型保持可维护。若实际需复杂框架或重写导入系统，按scope暂停自动拆分并请用户决定。无迁移；回退前端可保留已建组，原CLI继续恢复。
