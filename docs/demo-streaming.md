# 演示工作台与 AI 流式执行

2026-10-14，部署入口：https://soloops.23331.cloud/ 。

## 使用

登录页按钮下显示公开演示账号 `admin`、密码 `qwer123`，可点击“填入演示账号”。登录后默认进入生活杂货演示店，使用样例资料和通用渠道。

演示店包含 6 个商品、24 条近期订单、6 条库存快照、3 条客服消息和 3 份政策。数据由 `backend/scripts/setup_demo.py` 通过正常业务服务导入并保留 synthetic 来源。日期按初始化时点生成；后续演示持续使用时应按业务入口更新库存快照，24 小时后旧库存会明确显示过期。

首页 AI 入口支持经营问数、Listing、客服、今日运营。AI 任务默认预算上限 0.10 USD；确认本次发送范围后启动，页面实时显示 DeepSeek 生成的选择与执行状态。核对候选后批准保存，再从执行记录或业务页面回读。

## 初始化与配置

在后端配置 `SOLOOPS_DEMO_ENABLED=true` 后运行：

```sh
python scripts/setup_demo.py
```

脚本仅操作专用 `admin` 演示账号和 `demo-shop`。重复运行保留已有数据和后续编辑；已有同名普通账号必须显式采用 `--adopt-existing-admin`。关闭演示开关后登录页不显示演示凭据，正式账号创建与重置继续执行原密码规则。

服务器通过受保护的环境文件配置 `deepseek_chat` / `deepseek-flash`，密钥来源为部署者本机环境，不能进入源码、浏览器或日志。费率沿用当前部署估算配置，实际费用以供应商账单为准。

## 流式协议与业务状态

`POST /api/shops/{shop_id}/agent/runs/{run_id}/stream` 接受原有 `AgentAction`，每次推进一个节点。SSE 事件为 `status`、`delta`、`result`、`error`；浏览器使用同源 POST、会话与 CSRF 校验。反向代理关闭 buffering。

DeepSeek 请求使用真实 `stream=true` 与 usage 尾块。增量只用于待校验预览；完整模型结果仍经 schema、事实、版本、来源和预算验证后进入原业务服务。最终 `result` 与普通动作接口的任务对象一致。

执行线程独立管理数据库会话。连接中断不重新发起模型请求，服务仍结算当前已发起请求；未知费用保持阻断。来源清除后，交付前的独立可见性检查抑制新片段和已排队片段，上游继续完成费用结算。暂停、取消沿用现有状态机和审计记录。外部邮件或平台操作继续走对应业务入口的权限流程。
