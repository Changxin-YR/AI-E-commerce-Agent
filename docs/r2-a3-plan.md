# R2 A3：异常事项复核最小差异计划

日期：2026-10-10。前置：A2最终修复代码2f31e64105cf131314007046831870d45052dc78的准确CI成功。范围：SO-004/005/030/068的四类既有运营事项。

## 现状与差异

OperationTask/Event已有审批、完成、重开、版本、来源依赖和清除。完成仅是本地核对，当前没有对应原对象的新来源复检；消息来源也没有外部回复状态。复用这些实体和用户→店铺锁，只增加复核快照及既有事件的结构化详情，保留旧任务和原异常快照。

业务显示分为待核对、已核对待外部处理、已登记操作证据、待来源更新复检、新有效证据支持已解决、仍异常、已忽略或不适用。旧completed显示已完成核对；它不自动成为证据支持解决。人工记录包含说明、依据、发生时间、系统登记时间及当前卖家身份，明确是自报，不能生成外部回执。

## 复检口径

- 在原事项提供显式复检入口，固定原店铺/身份/渠道/订单时间窗/规则。来源已覆盖的旧事项仍可复检；已清除的内容不可恢复。规则变化需按新规则重新检查。
- 读取同对象当前来源，比较原始源行稳定键，不以标题模糊匹配。新的源行和数据时间必须晚于事项发现与人工操作时间，且在原时效小时数内；缺时间、未来时间、来源不匹配、部分导入组、缺对象/字段均保留待复检。上传时间不能替代业务更新时间。
- 库存：同SKU/渠道新快照，保持原安全阈值，数量达到阈值且快照有效才支持解除。
- 履约：同订单号+行号+SKU、同渠道，新导出来源明确fulfilled才支持解除；unknown待补证，partial/unfulfilled仍异常。取消或缺行不冒充已履约。
- 低毛利：固定原窗口/币种/阈值/当前成本估算模式，原订单行完整保留；新成本或订单来源可验证且计算完整，未舍入毛利率高于原阈值才支持解除。保持费用缺失/净利润未知。
- 客服：通用消息导入增加可选reply_status、reply_updated_at、reply_evidence；已回复必须有状态时间和凭据说明。字段保留在原始行/标准化JSON，不新增客服发送能力。仅新的同消息来源明确已回复且时间有效才支持解除，本地草稿/存档不参与此判断。
- 复检快照保留结论、原因、时间、来源行和店铺revision。后续来源变化或过期使结论待复检；撤销后恢复原值也不会自动复活。全部历次复检来源加入原任务清除依赖，清除任一依赖擦除复核正文和事件详情。

## 实施补充

- 旧status继续用于审批/完成/忽略，新增business_state解释业务结论；completed统一显示“已完成核对”。最新复核保存在task的可空JSON，事件保存同次结构化快照。恢复旧源行仍需显式复检；旧异常快照不改写为新数据。
- 消息的可选状态字段仅进入ImportRow.normalized；CustomerMessage投影显式排除这三个新字段。未提供状态时保持既有规范化JSON形状和同文件去重。来源“已回复”始终表示卖家文件声明，系统外发仍not_submitted。
- 原source_status继续说明原异常依据；复检来源另显示revision、有效期和原因。新结论在任何店铺数据revision变化后保守失效，防止撤销→恢复重新激活；复检结果已失效时原历史证据仍可阅读。
- 新请求沿用task.version，重复相同请求回读已保存事件；不同内容或并发过期版本409。重复复检同revision/来源/结果时不重复写事件。全部新增来源依赖去重追加，保留历史清除链。
- 每类复检读取最多10000当前记录，单对象证据超过1000行时拒绝存档并提示缩小范围。低毛利仅处理原SKU，逐一核对原订单键完整且仍计入，缺成本/币种冲突或数量不足仍待复核。
- 低毛利复用原窗口未改变的订单及成本来源；发生变化的每条来源必须具有有效的新导出时间，且至少一条证据变化。仅重新上传相同值、旧源行恢复或修改显示标题不能作为新有效证据。库存直接使用快照业务时间；消息同时校验回复状态时间和文件导出时间。
- 前端分别展示人工处理状态、原异常来源状态和最近复检结论；原异常明细与新复检来源可以分别展开。填写未保存的凭据时阻止切换事项，写入期间锁定页面相关操作；异步结果仅应用于发起请求的同店铺同事项版本。
