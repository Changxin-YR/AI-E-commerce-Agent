## 3. 任务定义与判定规则

用户消息及仓库没有预先编号的 T1～T9 任务定义。本报告将九项编号映射为下表，覆盖 R2 的基础经营链路。它们是本轮 UAT 任务编号，不替代原 SO、A、B 或 R2 工作包编号。

P0：数据破坏、越权或未经批准的外部动作；P1：目标用户的必要流程被阻断；P2：有可行路径但需额外指导、容易误操作；P3：轻微呈现问题。条件未满足与产品缺陷分别登记。没有观察到 P0，不代表穷尽安全审计。

| 任务 | 业务目标 | 本轮结论 | 问题等级 |
|---|---|---|---|
| T1 | 首次进入、经营档案、建店 | 建号需管理员；建店和档案前端通过 | P1：前端独立初始化边界 |
| T2 | 商品/订单/库存/消息导入及对账 | 小文件、重复与错误拦截通过；大文件需外部拆分 | P1：纯界面大报表路径；平台真实格式待验 |
| T3 | 独立核算销售额、历史成本与毛利 | 所测金额和缺失口径通过 | P2：日期/凭据时间输入门槛 |
| T4 | 今日异常、审批、完成、重开及复检 | 所测待办闭环通过 | 无阻断；真实补货未验 |
| T5 | Agent 受控执行、拒绝、失败恢复 | 本地确定性流程通过 | P2：刷新后新任务范围重置；真实模型待验 |
| T6 | Listing 审批、复制和导出 | 通用本地交付通过，事实门禁保持 | 平台刊登/模板待验 |
| T7 | 退款混合诉求、人工接管与客服草稿交付 | 本地草稿及自报语义通过 | P2：刷新后须重选历史草稿 |
| T8 | 新来源、旧结果失效及重新核验 | 所测失效/重算/解决判定通过 | 无所测阻断 |
| T9 | 日报、调度状态、退出/重启与回读 | 手动日报、启停和持久化通过 | 自动真实周期本轮未启用，仅技术测试覆盖 |

## 4. T1～T9 实际执行记录

### T1 — 首次进入与建立经营资料

**数据身份**：全新合成账号 `uat_seller`，合成店铺 #1，US / USD / Asia/Shanghai；不含真实姓名、地址或邮箱。

**用户操作过程**：打开登录页 → 展开“首次使用或忘记密码？” → 管理员使用正式 CLI 建号 → 用户登录 → 自动化与设置/经营资料 → 添加店铺 → 填写经营名称、经营模式和类目 → 保存 → 刷新回读。档案也在后续独立进入设置页补录，证明未强制先完善全部资料才允许运营。

**预期**：知道如何获得账号；能通过界面建立明确的业务归属、默认币种与时区，并持久保存。

**实际**：登录页仅提供“由本机管理员通过账号管理命令创建账号或重置密码”的说明，没有自助注册入口。管理员准备后，店铺和经营档案均保存成功。最终 `shops=1`、`seller_profiles=1`。

**证据**：[首次使用页](../../.local/seller-uat-20261010/evidence/T1-first-use.png)、[建店](../../.local/seller-uat-20261010/evidence/T1-created-shop.png)、[档案回读](../../.local/seller-uat-20261010/evidence/T1-profile-readback.png)、`T1-api.json`、`T1profile-api.json`、数据库最终快照对应两表。

**结论/严重程度**：已有账号后的页面操作通过；“未参与开发的卖家从零全程只用前端”未通过，P1 上手条件。它不是权限漏洞，也不要求降低账号安全规则。

### T2 — 导入、去重和完整性

**数据身份**：本轮独立编制的 SYNTHETIC 文件。文件名中的 Amazon/Shopify 表示选定来源渠道；字段使用 SoloOps 通用契约，**不代表真实平台原始导出格式**。

**用户操作过程**：按店铺、类型、渠道、合成身份及导出时间选择文件 → 上传 → 核对映射 → 校验预览 → 确认导入。依次导入 4 商品、Amazon 8 订单行、Shopify 1 订单行、2 库存、2 消息；重复导入 Amazon 同 8 行；再上传同文件内重复键的 2 行及 2001 行大报表。

**预期**：原始行数、有效数及覆盖影响可核对；重复不累计销售；错误和超限不能静默丢失或部分成功冒充完整导入。

**实际**：正常文件持久成功；重复导入后有效 `order_lines=9`，不是 17。两个相同订单行键的文件停在预览，确认导入禁用。2001 行文件显示“每个文件最多 2000 个数据行，请拆分后导入”。展开大报表指引后要求在本机运行拆分命令，再上传 manifest 和分片；没有全程前端的大文件拆分路径。技术测试另验证跨片重叠、部分覆盖、纠错、撤销与事务回滚，本轮未将其算作卖家用前端完成 2001 行导入。

**证据**：`T2-api.json`；[重复导入结果](../../.local/seller-uat-20261010/evidence/T2-committed-orders-reimport-SYNTHETIC.png)、[重复键预览](../../.local/seller-uat-20261010/evidence/T2-preview-orders-duplicate-key-SYNTHETIC.png)、[超限页面](../../.local/seller-uat-20261010/evidence/T2-large-file-blocked.png)、[拆分指引](../../.local/seller-uat-20261010/evidence/T2-cli-split-required.png)；数据库 `import_batches/import_rows/order_lines`；`test_import_groups.py` 本轮执行结果。

**结论/严重程度**：小文件导入和防重复通过；超过 2000 行的纯界面路径受阻，P1（相对于本轮前端独立操作目标）。手工歧义映射、分批导入等边界以技术测试佐证；真实 Shopify/Amazon 报表兼容未验。

### T3 — 销售额、退款、币种与成本

**数据身份**：同店合成订单及五份合成历史单位成本凭据；系统没有独立认证这些凭据的会计真实性。

**用户操作过程**：经营分析 → 选 Amazon/合成/USD 和七天窗口 → 当前成本回推估算 → 计算并展开订单行；改 EUR 单独计算；改历史成本模式，先观察未知；逐行录入凭据、币种、时间和确认 → 重算 → 保存分析 → 回读。

**预期**：结果与下节独立账表逐行相等；取消/未付款排除、退款不擅自恢复成本、币种不混加；缺成本保持未知，费用未全时不称净利润；历史结果使用具体订单行凭据。

**实际**：USD 净销售 `71.9700`，当前成本可核对子集 `49.3750`，配对完整毛利子集 `14.5950`，完整成本和毛利均 null。EUR 为销售 `24.0000`、成本 `10.0000`、毛利 `14.0000`。补齐五条 USD 历史成本后为成本 `47.0000`、毛利 `24.9700`。保留混合币种、退货件数及费用缺口提示。历史分析 #2 持久保存。

**证据**：[独立对照 JSON](../../.local/seller-uat-20261010/evidence/T3-independent-comparison.json)、[当前成本页面](../../.local/seller-uat-20261010/evidence/T3-current-cost.png)、[历史成本结果](../../.local/seller-uat-20261010/evidence/T3-history-confirmed.png)、[历史保存回读](../../.local/seller-uat-20261010/evidence/T3-history-saved-readback.png)；`T3-api.json`、`T3history-api.json`；`order_cost_revisions` 5 行及 `saved_analyses`。

**结论/严重程度**：所测业务口径通过。P2：统计起止、凭据及政策时间需要用户填写 ISO 8601 和时区偏移，缺少日历式操作；尚未量化真人误填概率。费用重复凭据测试通过，但不据此宣称费用已完整归集。

### T4 — 今日异常与真实业务状态

**数据身份**：同店合成库存/订单/消息；过期库存与当前库存分开。

**用户操作过程**：今日运营选范围 → 运行 → 查看四个候选 → 打开 UAT-CUP 低库存 → 批准 → 记备注并完成 → 重开 → 再完成 → 无新数据复检 → 重新运行今日运营。

**预期**：缺数模块不伪造结果；完成核对不等于补货；无新证据不显示解决；重复检查不增加同一有效异常。

**实际**：初次 4 个事项；完成后业务进展为“已核对待外部处理”，无新来源复检为“待来源更新”；重开可用。再次运行仍为 4 个事项。低库存 #2 的旧备注和完成历史持久保留。新有效来源解决路径见 T8。

**证据**：[检查结果](../../.local/seller-uat-20261010/evidence/T4-findings.png)、[完成但未解决](../../.local/seller-uat-20261010/evidence/T4-completed-not-resolved.png)、[无新证据复检](../../.local/seller-uat-20261010/evidence/T4-recheck-no-new-evidence.png)、`T4-api.json`；`operation_runs=2`、`operation_tasks=4` 和事件表。

**结论/严重程度**：所测流程通过，无阻断问题；其他三类异常的完整状态组合由本轮 `test_operation_rechecks.py` 技术测试补充。没有真实补货/履约结果验收。

### T6 — Listing 人工可用成果

**预期**：保存本地有效版本、完整保留事实及版本来源；未经批准或校验不通过不能交付；导出不代表发布到平台。

**证据**：[批准与导出](../../.local/seller-uat-20261010/evidence/T6-approved-export.png)、`T6-copied.txt`、实际 `T6-*.csv`、[编辑原因](../../.local/seller-uat-20261010/evidence/T6-edit-reason.png)、[新来源成果](../../.local/seller-uat-20261010/evidence/T8-fresh-listing-export.png)；`listing_versions` 最终 5 条，当前版与来源可回读。

### T7 — 客服混合意图与人工交付

**数据身份**：消息 UAT-MIXED：`Where is my order? Also refund it.`；同店合成订单、shipping/refund 政策和合成人工自报。

**用户操作过程**：界面录入两项政策及有效期 → 选择消息 → 确认订单关联并选择政策 → 生成本地回复草稿 → 人工编辑 → 存档 → 选择 English、全文审阅确认 → 复制/CSV 下载 → 登记明确标记的合成自报 → 从历史回读。
