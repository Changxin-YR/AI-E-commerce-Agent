# SoloOps · AI 跨境电商运营工作台

Vue 3 + TypeScript / Python FastAPI / MySQL 的个人卖家运营项目。后端采用接口层、业务服务层、数据访问层，业务数据与操作记录持久化。

目前已交付**账号与经营工作空间、四类文件导入、确定性经营分析、跨店经营总览与日周月摘要、Listing 本地审批、客服草稿与政策证据、今日运营巡检与待办、受控 Agent 执行、独立新品利润试算、经营规则与内部预授权、R2 测试外发、统一任务草稿审批驾驶舱**基础切片。P0 四条 MVP 的模型协议与本地业务闭环已用合成替身验证；同组合成资料的真实模型四流程已通过G-05验收，本人QQ邮件真实发送和收件已通过G-06验收，真实经营样本与平台接入按后续范围推进；完整进度以 [74 项功能矩阵](docs/feature-matrix.md) 为准。

## 本地启动

需要 Python 3.11+、uv、Node.js 24.12+ 和 Docker。以下命令在项目根目录开始执行；MySQL 仅绑定本机 3307，测试库绑定 3308。

Windows 本地验证建议使用 Node.js 24.16+；24.15.0 曾在浏览器回归期间原生退出，版本对照与官方修复资料见 [测试记录第二十八迭代](docs/testing.md)。

```powershell
python scripts/setup_local.py
docker compose --profile test up -d --wait
cd backend
uv sync --frozen --python 3.11
uv run alembic upgrade head
uv run python -m app.cli create-user owner
uv run uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

账号创建时交互输入至少 12 位密码。配置脚本生成随机数据库口令，保存在被忽略的本机 `.env` 中；已有配置时拒绝覆盖。也可以按根目录和 backend 的 `.env.example` 手动配置。

另开一个终端，从项目根目录执行：

```powershell
cd frontend
npm ci
npm run dev
```

打开 [本地工作台](http://127.0.0.1:5173)，用自己创建的账号登录。API 文档在 [OpenAPI 页面](http://127.0.0.1:8000/docs)。前端通过同源 `/api` 代理访问后端。

首次使用：登录 → 经营资料 → 添加店铺 → 数据导入 → 选择文件、报表类型和数据身份 → 核对映射 → 预览纠错 → 确认导入。可以先导入一类数据。界面提供 CSV/Excel 模板；[合成样本与字段说明](examples/imports/README.md) 可用于复现，上传这些样本时请选择“合成测试数据”。

同一店铺以 SKU 或“订单号+行号”识别记录；覆盖更新需核对新旧值并确认。批次可撤销和清除，恢复剩余有效批次的最新数据。导入保留明确来源、币种及时间。

经营分析：选择店铺、数据身份、订单渠道、币种和带时区的起止时间 → 选择受控问题 → 查看订单与成本来源 → 保存分析 → 创建核对待办。本页提供销售摘要、购买数量前五和低毛利筛选的本地快捷计算；可从入口打开 AI 经营问数。导入变化会使历史分析/待办需重算，清除来源批次会清理依赖的快照内容。

AI 经营问数：在 `/agent` 选择该流程 → 填写问题和固定统计范围 → 核对配置费率与美元预算 → 同意发送问题及匿名聚合事实 → 模型理解问题、调用确定性统计、组织事实解释 → 审阅并批准保存分析/核对待办 → 回读业务记录。正常流程需要两次模型请求，模型只能选择已验证事实及核对建议；数值、公式和来源由业务服务确定。原始订单号、SKU 名称、文件名与买家消息留在本地；问题原文会发送，需用户核对。默认示例关闭模型；协议、费用、审批及桌面/手机闭环已用替身验证。本轮百炼真实合成问数已完成意图理解、75/62/13金额核对及审批回读，见[G-05证据](docs/foundation-model-evidence.md)。

历史订单采用当前采购成本估算，缺折扣/退款/成本保留未知，异币种不换算，退款不恢复采购成本或库存。当前未归集平台、广告、物流和税费，因此只能判断已知商品毛利。默认窗口为最近 30 天（UTC 起止），可改为明确的 `2026-10-07T00:00:00+08:00` 至 `2026-10-08T00:00:00+08:00`；区间不含终点。导出时间未知时不能推断数据截至时间。

跨店总览：在 `/overview` 按登记平台/市场筛选并选择最多 20 家店铺 → 选择身份、日期、时区和币种 → 生成总览 → 逐店展开订单/成本、当前库存与消息来源 → 保存日、七日、三十日或自选摘要。默认对比此前相同日历天数，也可自选对比范围。金额按币种分别汇总，保留未知和已知子集；市场为店铺资料，不表示买家国家。库存按生成时的当前快照判断，消息未核实回复状态，净利润和营销表现待补数据。已存摘要可刷新回读或主动清除；来源变化/库存到期标记需重算，清除依赖批次擦除整份正文。本地摘要保存不触发邮件发送。

Listing 审批：只导入商品即可在 `/listings` 选择 SKU → 从事实模板生成草稿，或点击“生成 AI Listing 候选” → 核对来源、新旧文案与缺失项 → 修改并保存新待审版本 → 核对事实后批准或拒绝。AI 流程单独确认目标和商品事实发送范围、来源版本与美元预算，模型选择标题参数并排序完整描述；批准保存草稿后，进入 Listing 页面单独批准本地生效。标题保留完整商品名，描述保留全部参数行；新增事实需补充来源。百炼真实合成候选与事实覆盖已通过，真实商品质量和平台发布待进一步验证。历史文案可另存、重新批准；来源被覆盖或撤销后版本失效，清除批次会擦除关联文案和差异，保留必要处理记录。

商品质量：在 `/product-quality` 选择店铺、身份、渠道和可选 SKU 前缀 → 检查当前主档 → 筛选缺失/待核对项 → 查看商品字段及原始行 → 确认保存本地报告。每次最多 1000 个商品，超限缩小范围；相似 SKU、参数多值和有限描述关键词仅作人工核对线索。品牌、编码、图片、类目和平台要求明确未检查。历史报告可用固定链接回读，来源改变提示重检；清除依赖批次或主动清除会擦除正文。修改商品继续经源文件导入预览确认。

库存快照：在数据导入中选择“通用库存快照文件”，核对 SKU、已知可售数量、快照时间、安全阈值后确认；在 `/inventory` 按店铺/渠道/数据身份查询、展开源行。默认查询时效 24 小时，可调整后刷新；过期或无数据明确显示库存未知。修改阈值通过重新导入并确认差异，撤销/清除沿用导入批次入口。

今日运营：登录工作台选择店铺、数据身份、渠道，展开检查口径设定订单时间窗、币种、低毛利阈值与库存时效 → 运行检查 → 查看各分支和原始来源 → 批准候选为待办 → 记录备注、延期、忽略、完成或重新打开。商品成本取该店铺同身份主档；库存与消息取渠道当前导入投影。默认订单窗最近 7 天，库存时效 24 小时，低毛利购买量至少 1、毛利率不高于 20%，未启用经营规则时可按次编辑；启用后使用当前版本阈值。消息缺外部回复状态，订单缺实时履约证据时，只创建核对事项。重复检查保留已有处理状态；来源过期禁止批准，清除批次会擦除依赖的检查和待办内容。工作台直接检查使用 `local_rules`；受控技能运行、暂停与恢复可在 Agent 执行台使用。选择“AI 今日运营”可组织检查概览与核对建议。

AI 今日运营：从首页入口或 `/agent` 选择流程 → 设置范围与预算 → 核对分支状态/行数和候选数量 → 分别同意目标文本与聚合检查数据发送 → 审阅全部分支、缺失项和候选事实/来源 → 批准保存 → 跳转工作台逐项批准、完成或忽略。正常一次模型请求；全部候选由确定性检查产生，模型不能删减或执行它们。发送同意绑定检查快照，来源或时效改变需重新确认。概览与已知费用持久保存；未知费用不自动重试。桌面和手机闭环已经合成替身验证。

新品利润：在 `/profit` 选择店铺 → 填写单一结算币种、售价、采购价和依据 → 逐项填九类费用（固定单件金额或售价百分比）→ 复制/新增方案比较 → 展开公式、费用明细和敏感性 → 保存并从历史记录回读。未知费用留空；显式零也需依据。费用假设完整且售价费率合计小于 100% 时，给出向上取整的假设保本价。所有结果仅覆盖手填假设，不代表真实净利润。更改币种不会自动换汇。存档可清除其名称、金额和依据；独立试算不依赖导入订单。

收费类别规则：在 `/statements` 选择店铺、身份、渠道和预览窗口 → 新建映射规则 → 输入完整原始收费名、统一类别和理由 → 预览分类变化并展开来源 → 确认规则适用于此范围全部日期与币种 → 保存并回读当前账单分类。收费名区分大小写，未知/重复/币种及类别冲突保持待核。规则列表可查看调整历史、修订、撤销或清除；清除擦除规则全部历史正文，原账单与人工费用保留。分类结果为当前读取，规则保存不表示账单已核对，不能据此计算净利润。

人工核对结论：在同一账单页新建结论 → 填写窗口内核对依据及差异说明 → 预览账单/费用/规则 → 明确确认保存 → 查看固定链接和历史依据 → 回读当前来源、费用与规则 → 修订、撤销或清除。未知分类、缺失一侧、重复、异币种及类别冲突只允许存为待核；金额差异说明仍待后续处理。相关依据变更使结论待重核，恢复原值也须重新确认；清除任一历史来源、费用或规则会清除相关存档所有版本正文。费用完整性、结算到账及实际净利仍需独立证据。

结算与回款：在 `/settlements` 选择店铺、身份、渠道和周期 → 新建登记 → 填写精确原账单号、周期依据及最多 50 笔人工到账凭据 → 预览平台回款与人工声明的逐笔差额 → 明确保存 → 固定链接/当前回读/历史 → 修订、撤销或清除。平台回款和到账日期可晚于周期结束，原始行可展开；金额一致仍待银行核验，文件覆盖及余额保持未知。来源变化需重核，清除任一历史来源会擦除全部登记正文和数值历史；撤销释放原账单及人工凭据占用。正常验证使用合成数据。

经营规则：在 `/rules` 选择店铺、渠道和数据身份 → 填写库存有效小时、最低销量、低毛利率上限及依据 → 确认保存。今日运营和 Agent 自动加载当前版本；启用时须使用其阈值，规则变化后旧待审动作会被阻断。历史可回看、恢复为新版本；撤销/重置回到初始口径，历史保留。仓库、物流、品牌/客服话术、广告每日计划可记录依据，当前供人工参考。默认写入须逐次审批；保存异常候选可在 Agent 执行台设置有界 R1 预授权。

任务执行台：在 `/agent` 选择流程、来源范围、对象和预算 → 查看检查证据 → 批准内部保存 → 查看步骤和回读结果。支持暂停、恢复、取消、预算和熔断；默认本地规则/事实模板。自然语言目标用于受控路由，AI 经营问数与 AI Listing 具备独立的受控事实流程；客服和今日运营具备受控模型流程；本次真实验收进度见基础版本验收表。

R1 预授权：今日运营固定流程检查出候选后 → 在下方核对完整范围与恢复边界 → 设置 1—20 次、1—168 小时 → 确认保存 → 为当前候选使用授权，或按授权范围重新检查。每次保存消耗一次，重放不重复扣减；来源/规则变化或到期即失效。可撤销授权，已保存结果保留；另行撤回本次新增且未被后续处理的候选会设为已拒绝，保留审计且不返还额度。邮件外发属于独立 R2 门禁。

R2 测试外发：支持 QQ 邮箱发件。在 `/outbound` 连接并验证本人邮箱 → 选择已保存的运营检查 → 填写收件地址（默认本人，可指定其他单个邮箱）→ 审阅地址与全文 → 单次批准并提交。每份摘要最多提交一次，SMTP 250接受结果和实际收件证据分别记录；超时保留未知，人工核对原收件箱，不自动重发。已有Resend通道保留只读回执查询。默认关闭；QQ授权码配置、迁移及验收步骤见[使用维护](docs/foundation-user-guide.md#qq-邮箱配置与本人收件验收)。本人QQ真实收件验收已通过；本次临时外发开关已关闭，日常启用按该指南绑定运行实例的账号与店铺。

统一驾驶舱：首页按店铺、身份、渠道和类型汇总十类已有事项，显示实际最近运行、待审、待处理、失败、未知和需更新来源。打开一条记录会定位确切店铺/对象的原审批或报告；分析核对待办支持完成与重开。首页只读取本地记录，R2 未知结果仍在原邮件页按通道核对。详情见开发文档第十九节。

## 账号管理

在 `backend` 目录使用以下命令，密码由终端交互读取，不放进命令参数：

```powershell
uv run python -m app.cli create-user owner
uv run python -m app.cli reset-password owner
```

恢复密码会撤销该账号的全部现有会话。本地拥有数据库访问权限的管理员才应执行恢复命令。当前设计用于本机开发；公开部署前需要 HTTPS、Secure Cookie、入口限流和备份配置。

## 运行检查

先启动隔离测试库：`docker compose --profile test up -d --wait`。测试会清理指定的 `_test` 数据库，勿配置为真实业务库，后端测试和浏览器测试请顺序执行。

```powershell
cd backend
uv run ruff check app tests migrations scripts ../scripts
uv run ruff format --check app tests migrations scripts ../scripts
uv run mypy app
uv run pytest -q
cd ../frontend
npm run lint
npm run build
npm run test:unit
npx playwright install chromium
npm run test:e2e
```

`npm run test:e2e` 自动构建生产页面、启动 8001/5174 隔离 API 与页面预览服务，并创建合成账号。GitHub Actions 对 main 的推送和 PR 执行相同检查。测试报告见 [testing.md](docs/testing.md)。

## 本地定时检查与经营报表

打开“定时与通知”，选择店铺、数据身份、渠道、币种、运行时区和日/周/月周期，确认当前经营规则后保存。API 运行期间每 30 秒扫描到期计划；可通过 `SOLOOPS_SCHEDULER_ENABLED=false` 关闭扫描。检查结果保存在站内，候选通过原任务执行台逐次审批。

订单回看窗口为计划时刻向前 N×24 小时；库存等投影在实际执行时检查。停机后至多补最近一期，24 小时之外记录为错过；暂停/恢复从将来周期重新开始。夏令时重复时刻只取第一次，不存在的时刻跳过。免打扰只推迟未读提醒，完整运行历史随时可查看。

选择“经营报表”可确认按期保存日报、周报和月报。日报汇总前一自然日，周报每周一汇总上一完整周，月报每月 1 日汇总上一自然月，分别比较前一完整周期；按计划时区计算，币种分别统计。通知可打开原报告、查看依据与来源状态，来源批次清除同步擦除依赖报告正文。
